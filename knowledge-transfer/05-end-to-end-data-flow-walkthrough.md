# Module 05: End-to-End Data Flow Walkthrough

## Step-by-Step Lifecycle of a Sales Order Line

1. **Extraction & Seeding**: Raw order lines are generated by `src/etl/seed_data.py`.
2. **Dimension Resolution**:
   - `order_date_key` converts `'2024-01-15'` to `20240115`.
   - `order_location_key` looks up `DIM_LOCATION` where `location_id = 'LOC-001'` and `effective_start_date <= '2024-01-15' <= effective_end_date`.
   - `fulfillment_location_key` looks up `DIM_LOCATION` for `'LOC-002'`.
3. **Fulfillment Eligibility Validation**:
   - Check `fulfillment_location_type`.
   - If `'Warehouse'` or `'Manufacturing'`, proceed to fact loading.
   - If `'Sales Office'`, quarantine in `ETL_REJECT_LOG` with `reject_reason`.
4. **Fact Calculation**:
   - `gross_revenue = quantity * unit_price` (e.g. `10 * 1500.00 = 15000.00`).
   - `net_revenue = gross_revenue - discount_amount` (e.g. `15000.00 - 500.00 = 14500.00`).
5. **Atomic Load**: Insert record into `FACT_SALES_ORDER_LINE`.
6. **Aggregate Refresh**: Recompute `FACT_SALES_MONTHLY_AGG` totals by grouping atomic lines by `year_month`, `region`, `product_key`, and `location_type`.
7. **Reconciliation Audit**: Validate that atomic sum equals aggregate sum.
